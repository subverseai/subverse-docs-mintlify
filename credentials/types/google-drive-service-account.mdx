# Google Drive Service Account Credentials

Google Drive Service Account credentials let your SubverseAI agents work with files in Google Drive using server-to-server authentication — no person needs to sign in, and it works well for automated workflows that run on a schedule or in the background.

## Overview

Google Drive Service Account credentials provide access to:
- Listing, reading, and downloading files the service account can see
- Uploading, updating, moving, copying, and deleting files and folders
- Sharing files with specific people, a domain, or anyone with the link
- Secure, non-interactive authentication without user login

<Info>
  A service account has its own identity and its own storage — it does **not** automatically see files in your personal Google account. Either share specific files/folders with the service account's email (see Step 5 below), or, if you're on Google Workspace, turn on **domain-wide delegation** so the service account can act on behalf of a real user in your organisation. The alternative is the [OAuth2 API](/credentials/types/google-drive-oauth2-api) credential (sign in with your own Google account).
</Info>

## Steps to Create Google Drive Service Account Credentials

### 1. Set Up a Google Cloud Project
1. Visit the [Google Cloud Console](https://console.cloud.google.com)
2. Sign in with your Google account
3. Create a new project or select an existing one

### 2. Enable the Google Drive API
1. Navigate to **APIs & Services** > **Library**
2. Search for **Google Drive API**
3. Click **Enable**

### 3. Create a Service Account
1. Go to **IAM & Admin** > [Service Accounts](https://console.cloud.google.com/iam-admin/serviceaccounts)
2. Click **Create Service Account**
3. Enter a name and description (e.g., "SubverseAI Drive Integration")
4. Click **Create and Continue**
5. Skip optional role grants for now and click **Done**

### 4. Generate a JSON Key File
1. Click on the service account you just created
2. Go to the **Keys** tab
3. Click **Add Key** > **Create new key**
4. Select **JSON** and click **Create**
5. The key file is downloaded — keep it secure

### 5. Share Files or Folders with the Service Account
1. In Google Drive, open the file or folder you want the agent to access
2. Click **Share**
3. Add the service account email (e.g., `service-account@project-id.iam.gserviceaccount.com`) as an **Editor** (or **Viewer** for read-only)
4. Click **Send**

<Tip>
  Sharing a single top-level folder with the service account, rather than individual files, is usually easiest — anything you later add inside that folder is automatically accessible too.
</Tip>

### 6. (Optional) Turn on Domain-Wide Delegation

Only needed if you want the service account to act as a specific person in your Google Workspace organisation (so it sees exactly what that person's Drive shows), instead of only files explicitly shared with it.

1. In the service account details, note the **Client ID**
2. As a Google Workspace admin, go to **Admin console** > **Security** > **API controls** > **Domain-wide delegation**
3. Add the service account's Client ID with these three scopes (all three are required — Google checks every scope requested by SubverseAI against this exact list, so if even one is missing the connection fails with `unauthorized_client`):
   - `https://www.googleapis.com/auth/drive`
   - `https://www.googleapis.com/auth/drive.appdata`
   - `https://www.googleapis.com/auth/drive.photos.readonly`
4. When creating the credential in SubverseAI (next step), turn on **Impersonate a User** and enter that person's email address

### 7. Add to SubverseAI
1. Go to **Credentials** in your SubverseAI dashboard
2. Click **Create New Credential**
3. Select **Google Drive Service Account** from the credential types
4. Enter a name for your credential (e.g., "Production Service Account")
5. Fill in the required fields from your JSON key file:
   - **Service Account Email**: The `client_email` field
   - **Private Key**: The `private_key` field (including `-----BEGIN PRIVATE KEY-----` header)
   - **Project ID** (optional): The `project_id` field
6. Optionally turn on **Impersonate a User** and enter the email address of the Workspace user to act as (requires domain-wide delegation, Step 6)
7. Click **Save Credential**

## Required Fields

- **Name**: A descriptive name for your credential
- **Service Account Email**: The `client_email` from your JSON key file
- **Private Key**: The `private_key` from your JSON key file

## Optional Fields

- **Project ID**: The `project_id` from your JSON key file
- **Impersonate a User**: Toggle on to act as a specific Workspace user (requires domain-wide delegation)
- **Email**: The Workspace user's email address, shown only when **Impersonate a User** is on

## Usage Tips

- Grant the service account only the minimum necessary access — share only the files or folders it needs
- Rotate JSON keys periodically for security
- Use separate service accounts for different environments (dev/staging/prod)
- Store the downloaded JSON key file securely and never commit it to version control

## Troubleshooting

**File Not Found / Permission Denied (403)**: The file or folder hasn't been shared with the service account email — go back to Step 5 and share it, or confirm domain-wide delegation is set up correctly if you're impersonating a user

**Invalid JWT / Private Key Error**: Verify the `private_key` value includes the full PEM block — newlines must be preserved (use `\n` if pasting inline)

**API Not Enabled**: Ensure the Google Drive API is enabled in your Cloud project

**Service Account Not Found**: Confirm the `client_email` value was copied correctly from the JSON key file

**Can't See a File in a Shared Drive**: By default, Drive actions only look in "My Drive." Pass `includeSharedDrives: true` in the action's options to also search Shared Drives
