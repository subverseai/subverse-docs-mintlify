Speech-to-text models transcribe the caller's speech so the LLM can respond to it. Select one in the **Transcript Model** field of the [Voice Agent configuration](/agents/voice-agent-configuration#speech-detection-settings).

## At a glance

| Model | Provider | Model ID | Highlights | Official docs |
|---|---|---|---|---|

## Deepgram

### Nova 3

`nova-3-general` · [Official docs](https://developers.deepgram.com/docs/models-languages-overview)

Deepgram describes Nova 3 as its "highest-performing general-purpose ASR". It is recommended for meetings, multi-speaker, multilingual, noisy or far-field audio, in batch or streaming. Nova 3 does not include turn detection.

| Metric | Value | Source |
|---|---|---|
| Median word error rate (streaming) | 6.84%, vs 14.92% for the next-best competitor | [Deepgram](https://deepgram.com/learn/introducing-nova-3-speech-to-text-api) |
| Median word error rate (batch) | 5.26% | [Deepgram](https://deepgram.com/learn/introducing-nova-3-speech-to-text-api) |
| Test set | 2,703 audio files (81.69 hours) across multiple domains, including phone calls, drive-thru, conversational AI and voicemail | [Deepgram](https://deepgram.com/learn/introducing-nova-3-speech-to-text-api) |
| Code-switching | Real time across 10 languages (English, Spanish, French, German, Hindi, Russian, Portuguese, Japanese, Italian, Dutch) | [Deepgram](https://developers.deepgram.com/docs/models-languages-overview) |
| Keyterm prompting | Up to 100 key terms | [Deepgram](https://deepgram.com/learn/introducing-nova-3-speech-to-text-api) |

### Flux (English)

`flux-general-en` · [Official docs](https://developers.deepgram.com/docs/flux/quickstart)

Deepgram calls Flux "the first conversational speech recognition model built specifically for voice agents". It has end-of-turn detection built into the model, configurable turn-taking, and "Nova-3 level accuracy".

| Metric | Value | Source |
|---|---|---|
| End-of-turn detection latency | ~260 ms | [Deepgram](https://developers.deepgram.com/docs/flux/quickstart) |
| Agent response latency | 200–600 ms lower than pipeline approaches | [Deepgram](https://deepgram.com/flux) |
| False interruptions | ~30% fewer | [Deepgram](https://deepgram.com/flux) |
| End-of-turn timing | Fires within 1.5 s, 95% of the time | [Deepgram](https://deepgram.com/flux) |
| Accuracy | Word error rate comparable to Nova 3 Streaming | [Deepgram](https://deepgram.com/learn/fluxing-conversational-state-and-speech-to-text) |

### Flux (Multilingual)

`flux-general-multi` · [Official docs](https://developers.deepgram.com/docs/flux/quickstart)

Deepgram says this model "extends Flux to 10 languages with optional `language_hint` biasing": English, Spanish, French, German, Hindi, Russian, Portuguese, Japanese, Italian and Dutch. It has the same end-of-turn detection and barge-in handling as Flux (English).

Deepgram's Flux launch benchmarks (see [Flux (English)](#flux-english)) were published before the multilingual variant. No separate figures were found for this variant from Deepgram or from an independent source.

## OpenAI

### GPT Live Transcribe

`gpt-live-transcribe` · [Official docs](https://developers.openai.com/api/docs/models/gpt-live-transcribe)

OpenAI describes it as "a streaming speech-to-text model for applications that need low-latency transcript deltas from live audio". It supports tunable latency, free-form context, keyword hints and multiple language hints. OpenAI's realtime transcription guide recommends starting with this model.

| Detail | Value | Source |
|---|---|---|
| Latency setting | `delay` of `minimal`, `low`, `medium`, `high` or `xhigh`. Higher delay "can improve word error rate". | [OpenAI](https://developers.openai.com/api/docs/guides/realtime-transcription) |
| Not supported | Word-level timestamps, speaker labels, confidence scores, detected-language output | [OpenAI](https://developers.openai.com/api/docs/guides/realtime-transcription) |
| Benchmarks | Not published. No independent figures found. | — |

| Metric | Value | Source |

| Features | Automatic language detection, speaker diarization, 8 kHz telephony optimization | [Sarvam](https://docs.sarvam.ai/api-reference-docs/models/saaras) |

<Note>
  Sarvam now lists `saaras:v4` as its default, recommended model. Saaras v3 "remains available".
